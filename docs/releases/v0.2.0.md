# SkezMod v0.2.0

## Release

- Name: `SkezMod DB Repair + Null Guard + Signing Formatter Fallback`
- Channel: `stable-candidate`
- Target EXE: `MANAGPRE.EXE` (x86 PE, image base `0x00400000`)
- Target DB files: `DBDAT/EQ98030.FDI`, `DBDAT/JUG98030.FDI`

## What This Changes

### Database Repair

The patcher finds the linked `Stars` team roster in `EQ98030.FDI`, moves it off MANAGPRE's hard-coded special-club record id, and repairs every linked player payload in `JUG98030.FDI` that is shorter than the runtime-safe minimum length.

Investigated Stars roster:

```text
EQ record before repair: 9900
EQ record after repair: 9899
Team name: Stars
Linked players: 58, 115, 8425, 16955, 17126, 20863, 20864, 20865, 20866, 20867
```

The `9900` value is `0x26AC`, which MANAGPRE treats specially in search/profile display paths. Repointing the indexed EQ record to `9899` lets those surfaces use the normal team lookup result instead of the blank special-club string.

Payload changes in the investigated database:

```text
8425:  72 -> 80
17126: 70 -> 80
20863: 66 -> 80
20864: 73 -> 80
20865: 72 -> 80
20866: 64 -> 80
20867: 63 -> 80
```

Players `58`, `115`, and `16955` are already at or above the minimum and are left unchanged.

### EXE Patch

Only two EXE surfaces are retained:

- Null guard at `0x0066F1FB` in `FUN_0066F1F0`.
- Protects the `0x0066F208` `MOV AL,[ECX]` dereference path.
- Jumps to the existing empty-text path at `0x0066F243` when `ECX == NULL`.
- Signing-news formatter fallback at `0x00499DA1` in `FUN_00499D00`.
- Preserves non-null `{S3}`.
- Resolves nonzero event/team ids through `FUN_004B5C20`.
- Uses `Stars` only for the null `{S3}` plus zero event/team id path observed in the broken Stars signing feed.

No player-specific checks, search-row hooks, profile hooks, or branding strings are injected into the EXE.

The signing-news formatter path is not database-hydrated: event `0x453` can push a null `{S3}` club argument in MANAGPRE code. The formatter fallback is therefore retained as the narrow non-DB component needed for `You have signed <player> of Stars`.
