# SkezMod v0.2.0

## Release

- Name: `SkezMod DB Repair + Null Guard`
- Channel: `stable-candidate`
- Target EXE: `MANAGPRE.EXE` (x86 PE, image base `0x00400000`)
- Target DB files: `DBDAT/EQ98030.FDI`, `DBDAT/JUG98030.FDI`

## What This Changes

### Database Repair

The patcher finds the linked `Stars` team roster in `EQ98030.FDI` and repairs every linked player payload in `JUG98030.FDI` that is shorter than the runtime-safe minimum length.

Investigated Stars roster:

```text
EQ record: 9900
Team name: Stars
Linked players: 58, 115, 8425, 16955, 17126, 20863, 20864, 20865, 20866, 20867
```

Payload changes in the investigated database:

```text
8425:  72 -> 80
17126: 70 -> 80
20863: 66 -> 80
20864: 73 -> 80
20865: 72 -> 80
20866: 64 -> 80
20867: 63 -> 80
```

Players `58`, `115`, and `16955` are already at or above the minimum and are left unchanged.

### EXE Patch

Only one EXE patch is retained:

- Null guard at `0x0066F1FB` in `FUN_0066F1F0`
- Protects the `0x0066F208` `MOV AL,[ECX]` dereference path
- Jumps to the existing empty-text path at `0x0066F243` when `ECX == NULL`

No Stars strings, formatter fallbacks, player-specific checks, search-row hooks, profile hooks, or branding strings are injected into the EXE.

## Validation

Local validation on the investigated Stars database produced:

```text
dry-run changed payloads: 7
Stars slot count: 10
apply size delta: +80 bytes
runtime audit after repair: ok=True, issue_count=0, row_count=10
patched EXE SHA matched standalone nullguard-only patch output
```

The byte-for-byte EXE match confirms the patcher output is reduced to the null guard only when run from a clean executable.
